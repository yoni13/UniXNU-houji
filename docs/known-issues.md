# 已知问题与验证范围

## 图形与性能

Adreno 750 已完成真实命令提交、内存写回、完成同步和 iOS 桌面渲染，但持续交互仍会明显掉帧；打开应用可能短暂黑屏。单手模式黑色背景和最近任务阴影可能呈紫色，部分文字也可能异常。不能以桌面出现或时钟更新作为完整 GPU 驱动成功的依据。

已修正 Turnip 释放 BO 后再次清零、破坏被其他线程复用对象的竞态。早期局部对照曾不再出现同一种粉色块，但 r227 的用户反馈和照片仍显示大片粉紫色；该竞态修复没有解决所有颜色错误或卡顿。

GPU 工厂表包含 231、310、366、422、500、578、629、680、720、770、834、903 MHz。默认使用完整 903 MHz 上限，并由负载、触控和温度限制共同选择实际档位；旧 500 MHz 是历史试验值，不作为稳定性结论。r224 已记录 903 MHz 请求驻留，但卡顿未解决。提交 TLB、诊断采样、显示队列和 shader 预热路径也已修改，见 [性能修复与复测要求](performance.md)。HFI ACK 表示请求获得确认，不等于持续实测时钟。r224 的 TSENS 重读后无最终无效采样，部分 CPU 域曾触发结温限制；机身/电池温度与紧急关机仍未接入。

r224 与 r227 均有 `OutOfMemory(Device)`。系统配置的 8 GiB RAM 不等于 GPU 地址窗口；窗口高水位不能当成实际占用。r231 的 backboardd 窗口已扩大到 2 GiB 并进入桌面。空闲池回收、64 MiB 分配失败后的实际大小回退及地址碎片统计已作为匹配 bundle 在 r232 安装，r233、r234 进入桌面；r233 最终反馈未见乱码和粉色，r234 再次反馈粉色与卡顿，暂未见乱码。r235 的 128 段批量提交已生效，用户反馈整体更流畅，但单手模式上方空白和最近任务卡片阴影仍有粉色，本轮未反馈文字状态。其他客户端仍有槽位失败，不能称全部内存或渲染问题已解决。r235 预热生成 1165 个 pipeline、完成 26/135 个库，仍未完成。

纹理桥接原先遗漏 `allowGPUOptimizedContents` 和通道映射，运行时会使用默认值；源码已补齐属性传递、回读和带通道映射的纹理视图接口，并增加调用计数。r236 已运行这些修改，记录 2 次关闭优化的请求，没有非默认通道映射调用。用户仍见粉色，滑动与 r235 相近，打开应用动画仍很卡；没有达到 120 FPS 的证据。

`--diagnostic-fresh-pattern green` 是默认关闭的颜色定位构建选项，只改变新优化私有 RGBA8/BGRA8 纹理的初始填充值，并使用独立缓存身份。它不修改已绘制的颜色或导入 surface；不能当作正常渲染修复或性能对照版本。

r237 的绿色标记已生成 738 次初始化计划，但用户仍见粉色及文字乱码。这只对所覆盖的四种 8 位格式提供了排查线索，不能排除其他格式的初始化、shader 或合成问题。源码另修正七个异步函数/管线创建入口此前在调用线程同步编译的行为；r238 保留的桌面进程统计中这些异步入口调用全部为 0，用户仍反馈动画卡顿，不能把接口修正当成流畅性改善。

已尝试软件 120 Hz 通知和独立显示复制线程；物理刷新率、稳定 FPS 和端到端延迟尚未达标或完成测量。CPU 复制 framebuffer 与实际屏幕扫描是不同环节。r223 用户确认滑动撕裂、单手模式上方暗红/紫色，以及设置标题短暂串成其他选项；当前没有面板 TE/vblank 同步。见[设备测试](device-tests.md)。

r242 连续操作后用户反馈明显发热：CPU/GPU 最高结温分别为 98.1/85.3°C，CPU 已触发降频，温度无效采样计数为 0。旧策略在触摸续期期间强制请求最高频率，GPU 顶档请求占采样驻留约 55.27%。候选已改为活跃域/实际负载驱动的交互余量，并补充持久化 CPU 和显示耗时统计；仅通过主机检查与内核编译，降温和持续性能尚未实测。手机留在 Recovery 散热，没有继续压力测试。

## 输入与用户空间

原生 1200×2670 输出与全局键盘宽度适配已经分别在设置、主屏搜索和 App 资源库搜索中确认。触控能工作，但显示与调度瓶颈可能使操作体感迟滞。

墙纸资源、扩展注册和缓存适配只取得部分改善；墙纸预览、应用以及照片应用仍可能空白或黑屏。r224 快速滑动 App 资源库时可见壁纸短暂黑闪。Safari 页面原为纯黑：D22 设备树报告 P3 广色域屏幕，WebKit 因而用双平面 RGB10A8 表面绘制图层，Metal 翻译层只能以影子纹理替代（加载一页时影子纹理从 7 增至 46–50），结果为黑。2026-11-10 起启动参数 `houji_srgb=1`（选用）把 `/product artwork-display-gamut` 改为 `sRGB`，WebKit 改用 8 位 BGRA 表面；已实测 Safari 自身错误页与 `data:` 页面文字正常绘制，真实网站待联网复测。根本修复应在 Metal 翻译层支持 RGB10A8。主屏小组件仍为空白，原因不同，尚未查明。其他系统应用仍未完成系统性兼容验证。

r237 点击设置中的“通知”会闪退。两份本轮新增的 Preferences IPS 均在 MobileIcons 缩放图标、创建 `CIContext` 后进入 `CI::GLContext` 并访问空地址。r238 的三份新增报告确认软件 context 回退已执行，但仍进入同一 GL 路径并崩溃，故已撤下。r239 已验证 Preferences 的独立 256 MiB GPU 地址窗口和明确客户端名单生效；既有四个窗口不变。用户确认通知页可打开，本轮没有新增 Preferences IPS。仍需覆盖更多图标和进程重启场景。采集过程见[日志采集](log-capture.md)。

## 启动与恢复

UEFI 的 SCM 初始化存在间歇性停止现象。统一的超时恢复只能覆盖已经建立定时器、异常处理或内核恢复线程的阶段；安全固件调用阻塞、早期 CPU 启动故障或硬件挂死可能仍需要按键返回 OrangeFox。

Recovery 中可用的充电、声音、亮度或 USB 接口不能直接证明 iOS 中的对应服务可用。r229 的参数兼容修正使本机 DSI 亮度调节有了用户可见响应，DSI 日志无错误；完整亮度范围与熄屏/唤醒仍待验证。r263 已接通原厂 ADSP 电池服务，用户确认真实电量显示和 USB 插拔后的充电状态切换正常；充电控制、电流方向、持续净电量变化及电池温度保护仍待验证。无线、音频和深度休眠仍缺设备通路。

全部待完成项的优先级、依赖和验收条件见 [开发路线](roadmap.md)。

## 关于本机等待与壁纸异常

r239 用户确认“关于本机”点击后停在原页面，没有报告退出；本轮也无新增 Preferences IPS。r57 的历史调用栈曾停在 `PSGAboutDataSource::_macAddress` → SystemConfiguration 等待注册表空闲，但不能据此宣称 r239 已取得相同调用栈。当前候选参照 ios-apollo 的 InterfaceNamer 服务接入，并启用 Preferences 定向采样。

r239 新增的 PridePosterExtension SIGABRT 报告与驱动首错 `missing NBComputeEncoder globalTraceObjectID` 对应。候选在 Metal 对象基类补齐该追踪接口；它是否影响黑闪或视觉错误仍需设备验证。用户所述单手模式上方和任务卡片阴影的粉色、文字乱码仍保留为未解决项。


r240 后续反馈修正：About 最终能打开，问题收敛为首次长时间等待，二次进入未测。本轮定向栈被末尾统计覆盖，因此服务接入效果和剩余等待位置仍未确认。新增壁纸日志已变为 `NBCommandBuffer userDictionary` 缺失；下一候选补齐该对象状态，保留未知接口报错。r240 粉色和乱码未改善。

r241 两份保留栈确认 About 在读取网络地址时等待 IOKit 静止；网络服务已打开，注册表仍忙碌。构建仍启用 macOS 的 IOKit daemon 等待，而 iOS 根卷不存在该 daemon。r242 启用 XNU 的 `no_kextd` 模式后，实测根注册表不再忙碌；用户估计首次进入不到 10 秒、明显改善，但剩余延迟未消除。`userDictionary` 缺失及对应新增壁纸崩溃未再出现，r242 用户仍确认粉色和交互卡顿，不能将接口修正等同于画面修复。
